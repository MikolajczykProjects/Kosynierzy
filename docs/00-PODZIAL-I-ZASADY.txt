SENDER GLEIWITZ 31.08.1939 — PODZIAŁ RÓL I WSPÓLNE ZASADY (Unity, low poly 3D)
================================================================================
Ten plik czytają WSZYSCY. Każdy ma jeszcze swój plik z rolą.

GRA W 3 ZDANIACH
- Gra 3D z kamerą zza pleców (third person), styl low poly, płaskie kolory.
- Grasz Janem Wroną „Krukiem”, polskim agentem wywiadu (Ekspozytura nr 4, Katowice).
  31.08.1939 w Gliwicach zbierasz dowody, że napad SD na radiostację to niemiecka
  prowokacja: zdjęcia, rozkazy, kartka „Honiok, Franz. Konserve”. Uciekasz z filmem.
- Jedno trafienie = koniec misji. Strzał do cywila, policjanta albo pracownika
  stacji też kończy misję. Wojny nie zmienisz, możesz tylko ocalić prawdę.

ŻADNYCH SWASTYK ANI SYMBOLI NAZISTOWSKICH. Nigdzie: mundury, auta, flagi, ściany.
SD = szaro-zielone mundury bez naszywek. Bez krwi i makabry (Honiok przykryty płaszczem).


ROLE
--------------------------------------------------------------------------------
A. NATANIEL — MAPA + DIALOGI          plik: ROLA-A-MAPA-DIALOGI.txt
   Całe Gliwice 1939 w low poly, wnętrza, kolizje, nazwane punkty.
   Dialogi z głosami (ElevenLabs) i napisami.

B. UNITY — CAŁY KOD I SPINANIE        plik: ROLA-B-UNITY.txt
   Jedyna osoba, która pisze kod gry i edytuje główną scenę.
   Projekt, git, ruch, kamera, strzelanie, AI wrogów, zadania, UI, ekrany.

C. POSTACIE                           plik: ROLA-C-POSTACIE.txt
   Wszystkie postacie low poly z riggiem Humanoid i wbudowanymi animacjami.
   Jeden wspólny Animator Controller.

D. OBIEKTY                            plik: ROLA-D-OBIEKTY.txt
   Wszystkie przedmioty, rekwizyty, broń, pojazdy, drzwi, latarnie.
   Wbudowane animacje obiektów (drzwi, kable, karty, koła, światło).

Zasada: C i D NIE piszą kodu gry. Robią modele, materiały, animacje i prefaby.
B bierze gotowe prefaby i podpina pod nie logikę.


WERSJA I PROJEKT
--------------------------------------------------------------------------------
- Unity 6 (6000.x), szablon „Universal 3D” (URP). WSZYSCY ta sama wersja Unity.
- Projekt zakłada B w pierwszych 15 min i wrzuca na GitHub. Reszta: git clone.
- Edit > Project Settings > Editor: Asset Serialization = Force Text,
  Version Control = Visible Meta Files (w Unity 6 to domyślne).


FOLDERY — KAŻDY MA SWÓJ I NIE RUSZA CUDZYCH
--------------------------------------------------------------------------------
  Assets/_Mapa/        -> A (Nataniel)   prefab mapy, materiały mapy, Test_Mapa.unity
  Assets/_Dialogi/     -> A (Nataniel)   Resources/dialogi.json, Resources/Audio/*.mp3
  Assets/_Gra/         -> B (Unity)      kod, sceny, UI, Gra.unity, Menu.unity
  Assets/_Postacie/    -> C (Postacie)   modele, animacje, AC_Czlowiek, prefaby CH_*
  Assets/_Obiekty/     -> D (Obiekty)    modele, animacje, prefaby OB_*
  Assets/ThirdParty/   -> B              paczki z Asset Store / zewnętrzne

- Główną scenę Assets/_Gra/Sceny/Gra.unity edytuje TYLKO B.
- Każdy testuje u siebie na WŁASNEJ scenie testowej w swoim folderze.
- Dzięki temu w gicie nie ma konfliktów. Commitujesz tylko swój folder:
    git add Assets/_Postacie   (przykład)
    git commit -m "postacie: SD + Schupo"
    git pull --rebase && git push
- Pliki ProjectSettings/ i Packages/ zmienia tylko B. Potrzebujesz pakietu?
  Napisz B na Discordzie.
- Nie umiesz gita? Prawy klik na swój folder > Export Package > wyślij
  .unitypackage na Discorda. B zaimportuje.


SKALA I USTAWIENIE MODELI (bardzo ważne, inaczej nic nie pasuje)
--------------------------------------------------------------------------------
- 1 jednostka Unity = 1 metr. Człowiek 1,75–1,85 m. Drzwi 2,1 m. Piętro 3,5 m.
- Pivot (punkt zaczepienia) na DOLE, na środku podstawy (postać: między stopami).
- Przód modelu patrzy na +Z (niebieska strzałka w Unity).
- Rotacja i skala prefabu w roocie: 0,0,0 i 1,1,1.
- Collidery: proste (Box/Capsule), nie Mesh Collider na wszystko.
- Materiały URP/Lit, płaskie kolory, bez ciężkich tekstur. Smoothness ok. 0,1.

--------------------------------------------------------------------------------

  Rozmowa          bool    gestykuluje przy dialogu

  Siedzi           bool    siedzi (recepcja, fotograf)
